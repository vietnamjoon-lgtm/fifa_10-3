# 수신자 발밑으로 보내는 패스

2026-09-25. 사용자 요청: 선수보다 약 5m 앞에 가는 패스를 고치고, 선수를 공 쪽으로 움직이는 대신 공을 선수에게 보낼 것.

원인: `followPassEnabled`가 항상 false였고, 패스 목표에 수신자 속도에 비례하는 선행 거리와 스루패스 추가 거리를 더했습니다. 비행 중에는 목표를 보정하지 않고 수신자를 예상 접촉 지점으로 이동시켰습니다.

변경:
- 기본 추적 설정을 복구하고 패스 목표를 수신자의 현재 위치로 지정합니다. 이동 중에는 공의 수평 속도만 제한된 가속도로 보정하며, 가까워지면 감속해 발밑으로 들어갑니다.
- 패스를 받는다는 이유로 AI 선수에게 추가 달리기를 만들지 않습니다. 직접 이동 입력과 명시적인 침투 요청은 유지합니다.
- 수신자 자동 이동은 추적 패스에서 작동하지 않습니다. 물리 패스의 선택적 받기 지원도 직접 이동 입력을 덮어쓰지 않습니다.
- 수동 패스와 추적 끄기, 온라인 양 팀의 개별 설정을 존중합니다. 슛에는 추적을 적용하지 않습니다.
- 공과 선수 좌표를 순간 이동시키지 않으며 공중볼의 높이·수직 속도는 물리 계산에 맡깁니다.

공유 파일 `src/match.js` 변경 범위는 크로스의 선행 목표 덮어쓰기 방지, 패스 종류별 추적 설정 전달, 지정 수신자 외 동료도 공에 접촉할 수 있게 하는 세 곳입니다. 골키퍼 강화 코드는 유지했습니다.

검증: 전체 자동 검사 235개 통과, 웹 빌드 성공(131개 파일). 양 팀 × 패스/스루/크로스 × 8/18/32m의 18개 정지 수신 장면에서 선수 좌표가 전혀 변하지 않고 패스를 받았으며 접촉 거리는 1m 미만입니다. 이동 후 방향 전환, 수신자 선행 거리 제거, 골키퍼 손 패스·스로인, 동료/상대 차단, 추적 종료, 수동/온라인 설정, 공중볼 수직 속도 유지도 확인했습니다. 로그: pass-to-feet-tests.txt.

막히지 않은 고정 장면의 결과이며 모든 상황에서 패스 성공을 보장하지 않습니다. 실제 브라우저 조작 및 시각적 궤적은 확인하지 않았습니다. GitHub 쓰기 권한 오류로 업로드·공개 게임 배포는 아직 하지 못했습니다.
