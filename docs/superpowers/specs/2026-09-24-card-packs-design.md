# 카드팩 뽑기 시스템 설계 (Card Packs)

날짜: 2026-09-24
작성자: Claude (요청자: namseonghun37@gmail.com)
상태: 승인 대기

## 1. 목적

FIFA(FC 온라인) 얼티밋팀류의 "카드깡" 경험 — 코인으로 팩을 사고, 등급별 확률로 선수 카드를 뽑는 연출 — 을
이 저장소(`fifa_10-3`, PROJECT TOUCHLINE)에 새 서브시스템으로 추가한다. 뽑기 연출과 등급 시스템이 핵심이며,
뽑은 카드는 기존 선수 라이브러리(`squads.js`)에 바로 추가되어 라인업에 쓸 수 있다.

## 2. 범위 (Scope)

**포함**
- 실제 선수 이름을 쓰는 카드 풀(약 40명), 능력치·등급명은 자체 제작
- 코인(가상 화폐) 시스템: 최초 지급 + 경기 결과 보상
- 3단계 팩(브론즈/실버/골드), 팩별 확률표
- 팩 오픈 연출(등급별 색상·반짝임)과 결과를 선수 라이브러리에 자동 반영
- 자동 시뮬레이션 기반 테스트

**제외 (지금 안 함)**
- 실제 FC 온라인의 비공개 능력치 수치나 "불꽃" 같은 넥슨 고유 등급명 복제 — 등급명·수치는 전부 자체 제작
- 중복 카드 합성/판매, 시즌 이벤트, 리더보드, 온라인 대전과의 카드 동기화
- 선수 얼굴 사진(페이스온) 자동 적용 — 뽑힌 카드는 기본 얼굴로 생성, 원하면 기존 선수 편집 화면에서 개인이 추가 편집

## 3. 저작권/라이선스 메모

README의 기존 원칙(비공개 판정 수치·상용 선수 모델 비복제)을 유지한다. 실제 선수 "이름"만 사용하고,
능력치·포지션 배분·등급 구간·"브론즈/실버/골드/스페셜" 같은 등급명은 전부 이 프로젝트 자체 제작이다.
넥슨/EA의 고유 상표(예: "불꽃")나 비공개 수치는 사용하지 않는다.

## 5. 등급(Rarity) 체계

기존 `src/player-ratings.js`의 `overallRating(player)`(포지션별 가중 평균, 0-100)을 그대로 재사용해
카드 등급을 "계산된 값"으로 결정한다 — 별도 등급 필드를 손으로 정하지 않고, 능력치 수치가 등급을 결정한다.

| 등급 | 종합 능력치(overall) 구간 | 카드 수(목표) | 연출 |
|---|---|---|---|
| 브론즈 | 55 ~ 64 | 4 | 동색 테두리 |
| 실버 | 65 ~ 74 | 15 | 은색 테두리 |
| 골드 | 75 ~ 84 | 17 | 금색 테두리 + 은은한 광택 |
| 스페셜 | 85 ~ 99 | 6 | 무지개/반짝임 애니메이션, 공개 연출 시간 더 김 |

각 선수 카드의 능력치는 실제 기량 인식과 대략 맞춰 자체 제작한다(예: 메시·음바페는 스페셜, 신예는 브론즈).
정확한 스탯 수치는 구현 단계에서 `overallRating()` 공식에 맞춰 산출하고, 테스트에서 "의도한 등급 구간에
실제로 들어맞는지"를 검증한다(§12).

## 7. 코인(재화) 시스템

- `localStorage` 키 `touchline-wallet-v1`에 `{version:1, coins:number}` 저장 (squads.js의 `loadSquads`/`saveSquads`와
  동일하게 파싱 실패·비정상 값은 기본값으로 폴백)
- 최초 접속 시 기본 지급: **1000코인**
- 경기(연습 제외, `킥오프`/`친구와 1대1` 완주 시) 종료 시 유저 팀 기준:
  - 승리 **+150**
  - 무승부 **+50**
  - 패배 **+20** (참가 보상)
- `src/main.js`의 `onEvent()` 안 `type==='fulltime'` 분기에서 지급하고, `ui.toast()`로 결과 화면에 알림

## 8. 팩 종류 & 확률표

| 팩 | 가격 | 브론즈 | 실버 | 골드 | 스페셜 |
|---|---|---|---|---|---|
| 브론즈 팩 | 100 코인 | 65% | 30% | 5% | 0% |
| 실버 팩 | 250 코인 | 20% | 55% | 23% | 2% |
| 골드 팩 | 500 코인 | 0% | 30% | 60% | 10% |

- 팩 1개 = 카드 3장. 각 장은 독립적으로 위 확률표에서 등급을 추첨한 뒤, 해당 등급 내에서 무작위로 1명 선택.
- 같은 선수가 같은 팩 안에서 또는 이전에 이미 보유 중이어도 다시 뽑힐 수 있음 — 뽑을 때마다 새 `uid`를 부여해
  선수 라이브러리에 별도 항목으로 추가한다(같은 선수를 여러 장 보유 가능, FIFA와 동일한 느낌).

## 9. 뽑기 → 라이브러리 반영 흐름

1. 사용자가 팩 클릭 → 코인 잔액 확인 → 부족하면 토스트("코인이 부족합니다") 후 중단
2. 충분하면 즉시 코인 차감 → §8 확률로 카드 3장 추첨
3. 각 카드: `card-data.js`의 템플릿(0-100 표시 스탯) → `engineValue()`로 내부 스탯 변환 → `crypto.randomUUID()`로 새
   `uid` 부여 → `cleanProfile()`로 검증
4. 선수 라이브러리(`loadSquads()`로 불러온 현재 데이터)에 `players.push(...)` 후 `saveSquads()`로 저장
   - 라이브러리가 이미 200명(기존 상한)이면 팩 오픈을 막고 안내 메시지 표시
5. UI가 3장을 순서대로 공개하는 애니메이션 재생(등급별 색/반짝임, 스페셜은 더 화려하게)
6. "선수 편집으로 이동" 버튼으로 바로 라인업 배치 화면(`PlayerEditor`)으로 넘어갈 수 있게 연결

## 10. UI/UX

- 메인 메뉴 하단(`menu-footer`)에 `players-open` 버튼 옆 **"카드팩 ↗"** 버튼 추가
- 클릭 시 새 오버레이 패널(`card-packs-panel`), `players-panel`과 동일한 `overlay`/`dialog` 스타일 사용
  - 상단: 코인 잔액, 닫기 버튼
  - 팩 3종 카드형 UI(이름/가격/설명/확률 힌트)
  - 오픈 버튼 클릭 → 카드 3장이 순차적으로 뒤집히는 CSS 애니메이션(등급별 테두리 색: 동색/은색/금색/무지개)
  - 결과 화면: 카드 3장 요약(이름·포지션·종합 능력치·등급) + "라인업에서 확인하기" / "계속 뽑기" / "닫기"

## 11. 에러 처리

- 코인 부족: 구매 버튼 비활성화 + 클릭 시 토스트
- `localStorage` 접근 실패(시크릿 모드 등): 지갑은 세션 동안만 유지되는 기본값으로 폴백(기존 `loadSquads` 패턴과 동일)
- 선수 라이브러리 200명 초과: 팩 오픈 차단, "선수를 먼저 정리해 주세요" 안내
- 잘못된 팩 ID 등 내부 호출 오류: 방어적으로 무시하고 토스트로 안내(크래시 방지)

## 12. 테스트 계획 (`tests/card-packs.test.mjs`)

- `card-data.js`의 모든 카드가 `cleanProfile()`을 통과하는지
- 각 카드의 `overallRating()` 계산값이 §6에서 의도한 등급 구간 안에 실제로 들어오는지(등급 정의와 데이터의 정합성)
- 각 팩 타입으로 대량(예: 5000회) 시뮬레이션 시 등급별 실제 추첨 비율이 §8 확률표의 허용 오차(±3%p) 안에 드는지
- `wallet.js`: 기본 지급, 지급/차감, 잔액 부족 시 차감 거부, localStorage 라운드트립, 파싱 실패 시 폴백
- 팩 오픈 결과가 선수 라이브러리에 정확히 3명 추가되고 각 항목이 고유 `uid`를 갖는지, 200명 상한을 넘으면 거부하는지

## 13. 향후 확장(지금 범위 아님)

- 온라인 대전에서 상대에게 내 카드 공유
- 시즌 한정 카드, 실제 사진 기반 얼굴 자동 매칭
